## Prérequis

## Installation par navigateur

1. Dans le panneau de l’hébergeur, créer une base vide et un utilisateur autorisé sur cette base ; activer HTTPS et les extensions PHP.

4. Saisir les paramètres de la **nouvelle** base. « Vérifier la connexion uniquement » contrôle la connexion, la version et InnoDB sans créer de table métier ; l’assistant peut écrire son quota de tentatives dans l’espace privé.

L’espace privé est placé dans le dossier parent de la racine web, sous un nom `.musicband-…` propre au chemin de l’application. Le nom est déterministe, sans valeur secrète dans les sources. Conserver ce dossier lors d’une mise à jour ; un changement d’emplacement physique du site nécessite une reprise explicite du stockage. ## Diagnostic d’un formulaire qui se recharge sans résultat

L’installateur affiche sa version et un encadré de résultat contrasté. Après une erreur interceptée pendant le POST, il conserve uniquement le message en session et redirige vers une page GET ; aucun mot de passe n’est conservé dans la session. Cette redirection vise à éviter qu’un hébergeur remplace la réponse HTTP 400 par une page générique. Une session perdue produit un message explicite au lieu d’un rechargement silencieux.

Copier le message de l’encadré avec son étape et ses éventuels codes SQLSTATE/MySQL. Aucun message PDO brut ou secret n’est affiché ; les journaux PHP reçoivent uniquement l’étape, le type d’erreur et ces codes. La cause d’un HTTP 400 sans corps visible n’est pas établie par ce correctif d’affichage.

Le ZIP `musicband-toolbox-installateur-correctif-2026.10.22.6.zip` met à jour uniquement `install.php` et `css/common.css`, avec un guide. Décompresser dans le dossier web de la version 2026.10.22.5, sans toucher au dossier privé ou à la base. Pour revenir en arrière, conserver puis restaurer ces deux fichiers précédents ; aucune annulation SQL n’est nécessaire pour ce seul correctif.
